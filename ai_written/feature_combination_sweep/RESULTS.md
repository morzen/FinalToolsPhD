# Feature-combination sweep and TTP-only comparison: results in brief

Generated by `code/make_results_md.py`; every number below is read from `tables/sweep_metrics.csv` (and, for section 4, `tables/external_ttp_only.json`). Design, checks and how to run: `README.md`.

Metrics are the thesis' own: Top-k = share of queries whose true group has mid-rank <= k (what `evaluate_attribution` prints as precision); CTI score = 100 (1 - (rank - 1) / 162). **Sanity** = each of the 163 groups queried with its full profile; **stress** = with the seeded half of each feature type; **CTI (TTP reports)** = the 27 of the 29 CTI reports that contain TTPs (the same reports for every tool that has TTPs).

## 6. How to read it

* The stress test asks the tool to recover a group from half of its own profile. A combination with more feature types also hands the query more items, so part of the gain from adding a type is "more evidence", not "more information". For the 146 ATT&CK groups the CAPEC, CWE and CVE sets follow from the techniques (`../tables/ext_layer_redundancy.tex`).
* The CTI reports hold TTPs (27), software (3) and CVEs (1), so the CTI test can only show how the *profile* side of a combination changes the ranking of TTP evidence.
* GNN, Siamese and MIL are trained without a fixed seed (thesis Appendix 8.6), so a single training includes the variation of that training (measured in section 2).
* Methods are compared as they are; no significance test is made.
